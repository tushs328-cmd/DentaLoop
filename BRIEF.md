## 1. Идея
DentaLoop помогает зубным техникам и маленьким лабораториям не терять заказы и не срывать сроки.
Проблема: заказы на коронки, мосты и протезы живут в мессенджерах, блокнотах и памяти. Теряются оттенок (shade), особые пожелания врача, этапы работы и сроки.
Решение: единая доска заказов с этапами, автоматическими чек-листами по типу работы, предупреждениями о сроках и публичной ссылкой статуса для врача.
Почему уникально: идея основана на реальном опыте будущего зубного техника, с узкой профессиональной логикой (типы работ, этапы, оттенки по шкале), а не очередной todo-list.

## 2. Пользователи
- Зубной техник или маленькая лаборатория (основной).
- Стоматолог-заказчик (смотрит статус по ссылке без регистрации).

## 3. Ключевая функция (одна, до конца)
Создать заказ -> получить автоматический чек-лист этапов по типу работы -> двигать заказ по доске -> видеть риски по срокам -> отправить врачу ссылку со статусом.

## 4. Функции MVP (всё обязательно)
1. Создание заказа: код пациента (НЕ ФИО, подсказка про приватность), клиника/врач, тип работы, зуб/зубы, оттенок по шкале VITA (A1–D4), материал, срок сдачи, примечания.
2. Типы работ из встроенного справочника (минимум 6): циркониевая коронка, металлокерамика, мост, съёмный протез, винир, временная коронка. У каждого типа свой шаблон этапов (слепок/сканирование, моделирование, обработка, примерка, глазурь, контроль, отправка) с типовыми длительностями.
3. Канбан-доска по этапам с перетаскиванием и кнопками (доступно с клавиатуры).
4. Расчёт рисков: заказ подсвечивается "в срок / риск / просрочен" на основе срока сдачи и оставшихся этапов.
5. Публичная страница статуса заказа по ссылке (только код пациента, тип работы, этап, ожидаемая дата; без личных данных).
6. Печатная заказ-наряд (print CSS, A4) для заказа.
7. Данные хранятся локально (SQLite или JSON-файл на сервере; либо localStorage при статическом режиме). Кнопка экспорта в JSON и импорта.
8. Демо-данные (5 заказов), помеченные как "демо", с кнопкой "сбросить демо".
9. Интерфейс на русском и английском, переключатель языка.
10. Опциональный ИИ-режим: если задан LLM_API_KEY в .env или доступен OLLAMA_URL, кнопка "Подсказка по заказу" генерирует краткую памятку технику (на что обратить внимание для этого типа работы и оттенка). Без ключа кнопка работает в режиме "шаблонная памятка" и подписана "Без ИИ". Режим всегда виден бейджем. Шаблонный режим никогда не выдавай за ИИ.

## 5. Не делать
Авторизацию, платежи, мобильное приложение, интеграции с мессенджерами, медицинские рекомендации и диагнозы. В README и в интерфейсе: "Инструмент учёта заказов, не медицинский продукт".

## 6. Приватность
Не вводить и не хранить ФИО пациентов, только код. Показать подсказку в форме. Публичная страница не показывает персональных данных. Ключи только в .env.

## 7. Стек и запуск
Node.js 20 + Express, фронт на обычном HTML/CSS/JS (без сложной сборки), SQLite через better-sqlite3 или JSON-хранилище. Установка и запуск: `npm install` и `npm start`, порт 3000. Windows PowerShell. Дополнительно Dockerfile и docker-compose.yml (необязательно, если успеешь).

## 8. Дизайн
Аккуратный, спокойный, профессиональный. Без фиолетовых градиентов, без трёх одинаковых карточек, без эмодзи вместо иконок. Свой фирменный акцент (один цвет), нормальная типографика, тёмная и светлая темы, адаптивность, состояния загрузки и ошибок, контраст не ниже AA, подписи полей, фокус клавиатуры.

## 9. Агенты и параллельная работа
Можешь использовать собственных суб-агентов и параллельную работу, если ускоряет, но: один агент на один файл или модуль, без конфликтов правок, итоговую сборку и проверку делает главный агент.
